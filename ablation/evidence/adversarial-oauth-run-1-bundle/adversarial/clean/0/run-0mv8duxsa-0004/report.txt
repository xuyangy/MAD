      SQL injection vulnerability: the `customer` parameter is interpolated directly into the SQL query string instead of using a parameterized query.

      The function builds the query with a template literal: `select id, total from orders where customer = '${customer}'`. Any caller-supplied value for `customer` is embedded verbatim into the SQL text. If `customer` originates from user input (e.g., a request parameter), an attacker can supply a value like `' OR '1'='1` or `'; DROP TABLE orders; --` to alter the query logic or execute arbitrary SQL. This is in contrast to the adjacent function in the same file which correctly uses a parameterized query (`db.query("select id, total from orders where id = $1", [id])`), showing the established safe pattern was not followed here.
